# Privacy policy — WikiMasters Toolbox

Last updated: October 2, 2026.

WikiMasters Toolbox runs only on `https://www.wiki-masters.com/`. It reads card identifiers, titles, and rarity from the game's collection, global catalogue, marketplace, trade, peer-collection and pack responses to display average sale prices and count cards opened by rarity. For catalogue pages restored by the game without a network request, it also reads public card metadata from the game’s tab cache; ownership and friend fields are ignored. When you choose to open all available packs or enable automatic opening, it sends pack-opening requests to WikiMasters using the browser's existing game session. These requests consume available packs.

The extension stores average prices and fetch timestamps in the site's local browser storage. It reuses cached prices for 24 hours and cached price errors for one minute; old summary entries may remain until the site data is cleared. Successful price reads also store one observation per rarity per UTC day, retained for 90 days and bounded to 300 catalogue IDs. Observations contain catalogue IDs, rarity, checked time and average or absence of sales; they are shared between accounts because market prices are public. Request timestamps and server pauses are stored in tab session storage to preserve the read budget across reloads. No seller or buyer identities are stored by the price tools. It also stores the automatic-opening toggle, chosen interval, next scheduled time, optional manual pack limit, and a boolean indicating that pack opening is paused for the game’s human verification. The game manages its own verification popup; the extension does not read or store verification tokens. Pack and rarity counts and the optional daily reset setting are stored locally under the current WikiMasters account ID. Earlier shared counts remain stored separately and are not assigned to an account. The latest Toolbox opening run is stored in the tab's session storage so it survives a page reload. This summary includes the account ID, opening mode, time, result, and the received cards' IDs, titles, rarities, and pack numbers. It is replaced by the next run and cleared when the tab session ends. The statistics feature does not save a separate history of individual cards. Other card and pack data are kept in memory while the page is open. No analytics, advertising, or developer-operated server is used.

When you confirm a discard preview, the extension sends the selected possession IDs to the game’s native bulk-discard API. Discarding permanently consumes those cards. Sale/trade protection checks read the current account’s active sale and pending trade responses; only commitment IDs are retained in memory. The last discard journal stores possession IDs, titles, statuses and any game error messages locally under the account ID. Pending writes are stored as uncertain before the request so an interrupted reload never automatically repeats them. The journal is replaced by the next execution and remains until site data is cleared. Selection rules stay in memory and reset after reloading or changing account.

The extension sends requests only to WikiMasters. The browser includes the existing WikiMasters session when requesting prices or opening packs. The developer does not receive these requests or the user's account data. The extension does not request access to other websites or browsing history.

When you load the collection index, the extension requests the game's collection pages and total, and stores the identified copies locally under the account ID. Stored fields are catalogue ID, possession ID, title, snapshot rarity, shiny status, owner ID, favorite status, tag IDs and acquisition date, together with page progress and synchronization timestamps. The index may remain in site storage until that storage is cleared. Observed changes to the collection invalidate the saved pages and refresh the index after you have activated it. The extension reads relevant game response metadata to detect these changes; it does not save authentication headers, cookies or mutation request bodies.

To remove locally stored extension data, clear site data for `www.wiki-masters.com` in Chrome. You can reset the pack counts or disable automatic opening from the Toolbox panel on the game's `/pulls` page.

The collection ranking uses the existing local index and price cache. Sale proposals and active comparable listings remain in memory and reset on navigation or account changes. Comparable searches use the native free marketplace search, with catalogue ID, rarity and shiny matching, a ten-page ceiling and the shared price request budget. My sales keeps only listing identifiers, card metadata, starting/best/final amounts, end times and observed statuses in memory under the detected account; buyer and seller profiles are ignored. The native UI adapter reads only the displayed card's public metadata and exact possession ID from its component properties. It uses the game's search and buttons to open the selected copy; it never identifies a copy for a sale from its title alone.

Before native sale confirmation, Toolbox refreshes the complete collection and sale/trade protections and obtains the same per-account browser lock used for collection actions. Protected copies need an explicit acknowledgement. The player confirms the sale with the game's own button. The latest sale journal is saved locally under the account ID and contains catalogue/possession IDs, rarity, entered amount, time, observed result and the auction ID if returned. It is marked uncertain before allowing the native write and is never automatically retried. It replaces the preceding journal and remains until site data is cleared. Toolbox does not read the native mutation body or authentication data and leaves the game's requests and responses intact.

For questions, open an issue at [github.com/henchoznoe/WikiMasters-Toolbox](https://github.com/henchoznoe/WikiMasters-Toolbox/issues).
