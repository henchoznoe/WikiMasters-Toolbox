# Privacy policy — WikiMasters Toolbox

Last updated: October 2, 2026.

WikiMasters Toolbox runs only on `https://www.wiki-masters.com/`. It reads card identifiers, titles, and rarity from the game's collection, global catalogue, marketplace, trade, peer-collection and pack responses to display average sale prices and count cards opened by rarity. For catalogue pages restored by the game without a network request, it also reads public card metadata from the game’s tab cache; ownership and friend fields are ignored. When you choose to open all available packs or enable automatic opening, it sends pack-opening requests to WikiMasters using the browser's existing game session. These requests consume available packs.

The extension stores average prices and fetch timestamps in the site's local browser storage. It reuses cached prices for 24 hours and cached price errors for one minute; summary entries are retained for up to 30 days, bounded to 1,000 catalogue IDs and 2 MB. A failed refresh preserves the original successful fetch timestamp. Successful price reads also store one observation per rarity per UTC day, retained for 90 days and bounded to 300 catalogue IDs and 8 MB. Observations contain catalogue IDs, rarity, checked time and average or absence of sales; they are shared between accounts because market prices are public. Request timestamps and server pauses are stored in tab session storage to preserve the common 200-request hourly budget across reloads. Collection, prices, marketplace, route hydration, pack opening and discard requests share scheduling, timeouts and server pauses; native game requests remain unchanged. No seller or buyer identities are stored by the price tools. Under the detected account ID, it also stores the automatic-opening toggle, chosen interval, next scheduled time, optional manual pack limit, and a boolean indicating that pack opening is paused for the game’s human verification. The game manages its own verification popup; the extension does not read or store verification tokens. Pack and rarity counts and the optional daily reset setting are stored locally under the current WikiMasters account ID. Earlier shared counts and pack settings remain stored separately and are not assigned to an account; automatic opening defaults to disabled for an account without its own settings. The latest Toolbox opening run per account is stored in the tab's session storage so it survives a page reload. This summary includes the account ID, opening mode, time, result, and the received cards' IDs, titles, rarities, and pack numbers. It is replaced by the next run for that account and retained for up to seven days or until the tab session ends, with a maximum of ten accounts and 500 cards per summary. The statistics feature does not save a separate history of individual cards. Other card and pack data are kept in memory while the page is open. No analytics, advertising, or developer-operated server is used.

When you confirm a discard preview, the extension sends the selected possession IDs to the game’s native bulk-discard API. Discarding permanently consumes those cards. Sale/trade protection checks read the current account’s active sale and pending trade responses; only commitment IDs are retained in memory. The last discard journal stores possession IDs, titles, statuses and any game error messages locally under the account ID. Pending writes are stored as uncertain before the request so an interrupted reload never automatically repeats them. The journal is replaced by the next execution and remains until site data is cleared. Selection rules stay in memory and reset after reloading or changing account.

The extension sends requests only to WikiMasters. The browser includes the existing WikiMasters session when requesting prices or opening packs. The developer does not receive these requests or the user's account data. The extension does not request access to other websites or browsing history.

When you load the collection index, the extension requests the game's collection pages and total, and stores the identified copies locally under the account ID. Stored fields are catalogue ID, possession ID, title, snapshot rarity, shiny status, owner ID, favorite status, tag IDs/names, category, ATK/DEF, image-availability flag and acquisition date, together with page progress and synchronization timestamps. The index is fresh for five minutes, partially loaded pages may resume for fifteen minutes, and persisted indexes are retained for up to seven days, bounded to ten accounts and 16 MB in total. Oversized or unavailable persistence leaves the in-memory index available with an explicit storage warning. Observed changes to the collection invalidate the saved pages and refresh the index after you have activated it. The extension reads relevant game response metadata to detect these changes; it does not save authentication headers, cookies or mutation request bodies.

To remove locally stored extension data, clear site data for `www.wiki-masters.com` in Chrome. You can reset the pack counts or disable automatic opening from the Toolbox panel on the game's `/pulls` page. Every supported page has Data & caches controls showing synchronization dates, size and retention limits, and buttons to clear the current account's collection index, shared price summaries or shared observations separately. Personal statistics, settings and action journals are durable records rather than expiring caches, and these cache buttons leave them intact. Clearing price observations deletes the local history; it cannot restore past unobserved prices. Compatibility diagnostics contain only fixed status messages and remain in memory. Account changes clear personal controls and cancel pending Toolbox requests.

The price inspector also keeps a local sample of explicitly concluded native market sales observed in the free market history and visited auction responses. It stores only auction ID, catalogue ID, snapshot rarity, shiny status, final amount and auction end time, under the detected account ID, plus the observation timestamp for cache management. Seller/buyer identities, possession IDs and card titles are omitted. The sample includes at most 1,000 auctions per account from the last 30 days by auction end time; storage is bounded to ten accounts and 2 MB total. Repeated observations are deduplicated; active, unsold, cancelled, incomplete and future-dated results are excluded. No detailed paid sales endpoint is requested. A local median requires at least five sales on three distinct UTC end days; the indicative quartile range requires ten sales on three days. The incomplete sample is separate from native averages and the daily average graph. Data & caches can clear the current account’s concluded-sale sample with confirmation. Collection valuation is calculated in memory from known native rarity averages; shiny copies without a separate native price are reported as unvalued. Sale/trade views recommend prices checked within 15 minutes, while the shared summary cache retains its 24-hour reuse policy for browsing. Targeted refreshes use the common request queue and preserve the successful timestamp on failure.

The collection ranking uses the existing local index and price cache. Sale proposals and active comparable listings remain in memory and reset on navigation or account changes. Comparable searches use the native free marketplace search, with catalogue ID, rarity and shiny matching, a ten-page ceiling and the shared price request budget. My sales keeps only listing identifiers, card metadata, starting/best/final amounts, end times and observed statuses in memory under the detected account; buyer and seller profiles are ignored. The native UI adapter reads only the displayed card's public metadata and exact possession ID from its component properties. It uses the game's search and buttons to open the selected copy; it never identifies a copy for a sale from its title alone.

Before native sale confirmation, Toolbox refreshes the complete collection and sale/trade protections and obtains the same per-account browser lock used for collection actions. Protected copies need an explicit acknowledgement. The player confirms the sale with the game's own button. The latest sale journal is saved locally under the account ID and contains catalogue/possession IDs, rarity, entered amount, time, observed result and the auction ID if returned. It is marked uncertain before allowing the native write and is never automatically retried. It replaces the preceding journal and remains until site data is cleared. Toolbox does not read the native mutation body or authentication data and leaves the game's requests and responses intact.

Collection filters, advanced sorting and duplicate grouping run in memory over the loaded index and existing exact-rarity price cache, without extra price requests. The extension stores up to 30 named filter queries per account with their save and last full-index synchronization times, plus the compact-layout preference used on collection and catalogue pages. The versioned preferences contain filter criteria and sort order, never a frozen list of possession IDs. Queries are recomputed against the current index; missing metadata and shiny prices remain explicitly unknown. Older indexes without the new metadata require a collection refresh to use those filters. These durable preferences remain until a view is deleted in Toolbox or site data is cleared; account changes reset the active query and selection. Sale/trade availability is shown only after the existing protection check; catalogue-level commitments are not assigned to an arbitrary copy.

For questions, open an issue at [github.com/henchoznoe/WikiMasters-Toolbox](https://github.com/henchoznoe/WikiMasters-Toolbox/issues).
